# Möbius-transformed trapezoidal rule in Python

Python implementation of the Möbius-transformed trapezoidal rule of

> Y. Suzuki, N. Hyvönen, and T. Karvonen. "Möbius-transformed trapezoidal rule". AMS Mathematics of Computation 95 (2026), no. 359, 1491–1515. DOI: [10.1090/mcom/4084](https://doi.org/10.1090/mcom/4084)

It approximates integrals $\int_{\mathbb{R}} f(x)\rho(x)\,dx$ by mapping the real line to the circle with $x = \mathrm{loc} - \mathrm{scale}\cdot\cot(\theta/2)$ and applying the trapezoidal rule with shifted equispaced points $\theta_k = (2k-1)\pi/n$. The default `scale=1`, `loc=0` is the transformation of the paper and of the Matlab code `cot_trap.m`.

The only dependency is NumPy.

The Python and Julia code was generated by Claude, Anthropic's AI assistant, based on the Matlab version written by Yuya Suzuki.

## Usage

```python
import numpy as np
import moebius_trapezoidal as mt

# ∫ |x| φ(x) dx with the standard Gaussian density φ, exact value sqrt(2/π)
mt.integrate(np.abs, 257)                      # 0.79788...

# other weights: "gaussian" (default), "logistic", any callable, or None for ∫ f(x) dx
mt.integrate(lambda x: x**2, 729, "logistic")  # π^2/3
mt.integrate(lambda x: np.exp(-x**2), 81, None)  # sqrt(π)

# a weight that is not centred at 0, here the density of N(1, 2^2)
rho = lambda x: np.exp(-(x - 1)**2 / 8) / np.sqrt(8 * np.pi)
mt.integrate(lambda x: x, 243, rho, scale=2.0, loc=1.0)  # 1.0

# nodes and weights, e.g. to reuse expensive function values
x, w = mt.nodes_weights(257)
value = w @ np.abs(x)

# vector valued integrands: f returns an array of shape (number of nodes, ...)
mt.integrate(lambda x: np.stack([x**2, x**4], axis=1), 243)  # [1, 3]

# a scalar function that does not accept arrays
import math
mt.integrate(lambda x: math.cos(x), 243, vectorized=False)  # exp(-1/2)

# automatic refinement until a tolerance is met
result = mt.quad(np.abs, rtol=1e-8)
result.value, result.error, result.n, result.converged
```

`quad` triples the number of points in each step, n, 3n, 9n, …, so that all previous function values are reused, and stops when the difference between the last two approximations is below `max(atol, rtol * |value|)`.

Nodes whose weight underflows to zero far in the tails are skipped, so `f` is never evaluated there. Use `nodes_weights(n, prune=False)` to get all `n` nodes.

## Randomly shifted rule with an error estimate

The module `moebius_trapezoidal_randomized` replaces the fixed half step shift by a uniform random shift, $\theta_k = 2\pi(k+u)/n$ with $u \sim \mathrm{Uniform}[0,1)$. Each shifted rule is an unbiased estimate of the integral, so repeating it with independent shifts gives an estimate together with its standard error.

```python
import numpy as np
import moebius_trapezoidal_randomized as mtr

r = mtr.integrate_randomized(np.abs, 257, n_shifts=16, rng=1)
r.value, r.std_error          # value ± 2 * std_error is an approximate 95% confidence interval
r.estimates                   # the 16 individual estimates

x, w = mtr.shifted_nodes_weights(257, 0.3)   # nodes and weights for a given shift
```

The total number of function values is `n * n_shifts`. All options of `integrate` (weights, `scale`, `loc`, vector valued integrands, `vectorized`) are available.

The second randomized rule, `integrate_rmt`, is the randomized Möbius-transformed trapezoidal rule of Definition 4.1 in [arXiv:2407.13650](https://arxiv.org/abs/2407.13650). Each sample also draws the number of points $M$ uniformly from $\{\lfloor n/2\rfloor, \dots, n\}$, which improves the worst-case root-mean-squared error over the weighted Sobolev space of smoothness $\alpha$ to the optimal order $n^{-\alpha-1/2}$ (Theorem 4.2 therein), half an order better than with a fixed $n$. The gain is in the worst case: integrands with strong oscillations at a frequency close to $n$ after the transformation are aliased completely by a fixed $n$, but not by a random $M$. For integrands whose transformed Fourier coefficients decay regularly, such as $\lvert x\rvert$, both rules converge at the same rate, and `integrate_rmt` has a somewhat larger error since it uses about $3n/4$ points per sample on average. `examples/rmse_comparison.py` compares the two rules.

```python
r = mtr.integrate_rmt(np.abs, 257, n_samples=16, rng=1)
r.value, r.std_error, r.points   # points: the number of points M of each sample
```
